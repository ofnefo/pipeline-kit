# Explicit public release

The public tree is a curated distribution. No refresh job copies a private snapshot or plugin cache. Runtime data and internal receipts belong outside this package or in ignored `.local/`.

Choose checks by the actual change before following this checklist. For prose-only updates, inspect wording/links and run the privacy scan and archive validation; reuse the recorded runtime baseline when its inputs are unchanged. For skill/profile/setup changes, test installation from the relocated archive and the affected instructions. Run browser/media/live-provider checks only if their behaviour or claimed validation changed. New runtime/dependency releases and a first installation need the full applicable baseline below. Record reused evidence with its source version; never describe an unrun check as freshly passed.

1. Review `provenance.json` and `release-files.json`. Every upstream entry identifies a selected source file and source digest. New files require an explicit file-list edit and review. `python tools/release.py source-status --roots <private-root-map.json>` reports changed upstream inputs without copying them. The root-map uses the source ids in provenance and stays private. Port approved changes individually, reapply configurable paths/safe defaults, update source hashes and inspect the diff.
2. Run `python tools/release.py scan --output .local/privacy.json`. Add `--denylist <private-identities.json>` for operator-specific names, products and hosts. The scanner records file/line/rule only, never matched secrets. Automated scanning supplements review; it cannot certify that arbitrary prose is anonymous.
3. Create a fresh Python 3.12 virtual environment and install `requirements-test.txt`; additionally install `requirements-office.txt` to cover optional Office acceptance. Run `python -m pip check`, `python -m pip freeze` and `python -m unittest discover -s tests -v`, retaining outputs outside public files. Verify Python compilation and JS module syntax. A skipped optional check is not a verified component.
4. Start `python pipeline_kit.py --workspace <fresh-test-directory> serve` on loopback. In a separate browser-testing environment install the explicitly chosen Playwright version/browser. Run `python tools/browser_check.py --output <private-evidence-directory>`. Inspect the 1440/375 screenshots against the existing Control layout. Walk project creation → file upload/edit → task creation/change → Studio chat persistence → local export. Test configuration of a local model only if claiming that optional adapter in the release. Stop only your test server.
5. With FFmpeg/ffprobe installed, render a synthetic video and audio fixture, probe dimensions/duration/codecs and inspect/listen to the output. Record executable versions and receipts. No inherited host results count. Office/PDF/OTIO extras need their own installed-environment receipts if promoted as verified.
6. Build an immutable candidate: `python tools/release.py build --output .local/pipeline-kit-candidate.zip`. Extract it into a new location, verify `BUILD_MANIFEST.json` hashes, repeat startup and integration checks there, and confirm no original source tree is needed. Builder excludes files not explicitly listed, rejects symlinks/junctions, refuses overwriting and blocks detected privacy findings. It does not commit, upload or approve a release.
7. Review the actual change: routine prose needs self-check, shared behaviour one independent reviewer, and agent-rule/security/destructive or production changes independent implementation and acceptance reviewers. Reviewers inspect the exact candidate digest, original request and corrections, changes, licences and evidence. Author-written exclusions cannot remove requested outcomes. Fix blockers and rerun only invalidated checks. Update `VALIDATION.md` honestly before the final candidate. Publication is a separate operator action after review. No explicit licence is granted for original source; preserve the bundled third-party licences. Never label an unreviewed candidate final-ready.

The included source hash map is provenance, not a signed trust root. `BUILD_MANIFEST.json` is the exact candidate-content receipt. Keep private source locations, personal denylist values, logs containing user paths and reviewer discussion out of the public archive.
