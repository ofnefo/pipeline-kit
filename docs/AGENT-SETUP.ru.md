# Агенты и скиллы

Для агента, который подключает Codex, Claude Code или другой клиент к рабочим проектам. Результат — одинаковые правила работы и проверяемая передача задач между сессиями.

## Общие настройки

Для установки готового набора по задачам используйте [AUTO-SETUP](AUTO-SETUP.ru.md) и `tools/setup_skills.py`: он выбирает скиллы по профилям, устанавливает их в проект и проверяет хеши. Следующие шаги описывают подключение правил и проверку работы клиента.

В каждом рабочем проекте задайте четыре значения: абсолютный `KIT_ROOT`, абсолютный `PIPELINE_KIT_WORKSPACE`, идентификатор карточки NameNode и стабильный ID сессии, например `codex:layout-demo`. `KIT_ROOT` — соглашение этой инструкции, не встроенная настройка Kit. `PIPELINE_KIT_WORKSPACE` читает CLI доски задач; основной CLI также получает путь через `--workspace`.

В PowerShell до запуска агента:

```powershell
$env:PIPELINE_KIT_WORKSPACE = (Resolve-Path ..\pipeline-workspace).Path
```

В bash/zsh используйте `export PIPELINE_KIT_WORKSPACE="/absolute/path/to/pipeline-workspace"`, заменив пример своим путём. Для уже запущенного приложения изменение переменной в другом терминале не действует: задайте её в окружении запуска либо откройте новую сессию из этого терминала.

Скопируйте содержание [AGENTS.template.md](../agents/AGENTS.template.md) в проектные правила, дополнив четырьмя значениями. Если правила уже существуют, сохраните копию и объедините их; не заменяйте чужие требования целиком. Это правила для рабочих проектов, а не повод менять глобальные настройки всех агентов.

## Codex

Разместите проектные инструкции в `AGENTS.md` в корне рабочего проекта. Проверьте, нет ли более приоритетного `AGENTS.override.md` и вложенных правил. В новой сессии попросите агента перечислить применённые файлы правил и рабочий каталог. Механизм загрузки описан в [официальной документации](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

Для обнаружения скиллов разместите выбранные каталоги в `<project>/.agents/skills/`. Каждый каталог должен содержать `SKILL.md`. Сначала используйте копирование, чтобы установка не зависела от поддержки ссылок ОС. Каталог `skills/` внутри дистрибутива сам по себе не гарантирует обнаружение клиентом. См. [документацию скиллов Codex](https://learn.chatgpt.com/docs/build-skills).

## Claude Code

Разместите проектные инструкции в `CLAUDE.md`. Если общие правила уже находятся в корневом `AGENTS.md`, добавьте в `CLAUDE.md` строку `@AGENTS.md`, сохранив остальные инструкции. Проверяйте загрузку в новой сессии. См. [документацию памяти проекта](https://code.claude.com/docs/en/memory).

Выбранные скиллы копируйте в `<project>/.claude/skills/<skill-name>/SKILL.md`. Их использование и настройки вызова описаны в [документации Claude Code](https://code.claude.com/docs/en/skills). Названия моделей и доступные режимы проверяйте в установленном клиенте и своей учётной записи; Kit не переключает модель внешней сессии.

## Другие агенты

Используйте механизм проектных инструкций вашего клиента. Если автоматической загрузки скиллов нет, передайте агенту точный путь к нужному `SKILL.md` и потребуйте прочитать его до работы. Подключение считается успешным после практического задания, а не после копирования файла.

## Как переносить и использовать скиллы

1. Выберите скиллы по задаче из [манифеста](../agents/skill-manifest.json). Прочитайте их инструкции и ссылки на вспомогательные файлы.
2. Скопируйте нужные каталоги вместе с их ресурсами в проектное расположение клиента. Для каждого сохраните исходную версию Kit и список локальных изменений.
3. В проектных правилах укажите, что команды `modules/...`, `apps/...` и `pipeline_kit.py` из скиллов выполняются из `KIT_ROOT` Python-интерпретатором его окружения. Пути к исходникам проекта и результатам передавайте абсолютными. Копирование одного `SKILL.md` не переносит программные модули.
4. Попросите агента выбрать скилл для маленькой задачи, прочитать его, проверить `--help` нужной команды и получить результат в тестовом проекте.
5. Проверьте результат по критериям скилла. Зафиксируйте, какой файл был загружен, какие команды выполнены и где лежит результат.

Полный комплект специализированных дизайн-навыков не является зависимостью базовой установки. Если нужен Blender, CAD, Photoshop, Illustrator или генерация, подключите соответствующий инструмент и отдельный скилл из выбранного вами источника. Проверьте происхождение, необходимые файлы, команды, совместимость и контрольный пример. Скилл с названием редактора не устанавливает сам редактор и его мост управления.

## Рабочий процесс для дизайна

| Этап | Действие агента | Проверяемый результат |
| --- | --- | --- |
| Бриф | Уточнить назначение, аудиторию, формат, размеры, исходники и ограничения | Краткий бриф и критерии приёмки |
| Направление | Выбрать референсы и объяснить подходящие свойства | Согласованное направление |
| Проба | Сделать один характерный образец до всей серии | Образец и решение владельца |
| Производство | Выполнить серию выбранным инструментом, сохранив исходники | Редактируемые материалы и экспорты |
| Визуальная проверка | Сравнить с референсами, проверить иерархию, читаемость, кадрирование и согласованность | Просмотр результата в размере использования |
| Техническая проверка | Проверить размеры, PPI, поля и формат по заданию | Отчёт preflight; отдельно ограничения по цвету/печатному процессу |
| Передача | Разделить мастер, финальные файлы и превью | Понятная структура выдачи и решение владельца |

Для встроенного растрового маршрута используйте `graphic-production`: `inspect_assets.py`, `compose_layers.py`, `make_contact_sheet.py`, `preflight_print.py`. Команды находятся в [MODULES.md](MODULES.md). Технический PASS не заменяет просмотр изображения и творческую приёмку.

## Роли и полномочия

Один агент может последовательно выполнять планирование, реализацию и документирование. Независимый проверяющий нужен для оценки изменений общих инструментов и правил; автор не выдаёт собственную проверку за независимую. Несколько исполнителей подключаются только для раздельных задач с явным владельцем файлов.

Запишите выбранную модель, режим рассуждения при наличии, доступные инструменты, разрешённые каталоги и ограничения сети в локальный профиль сессии. Используйте настройки самого клиента. [model-policy.example.json](../agents/model-policy.example.json) — шаблон договорённостей, не исполняемый конфиг Codex или Claude.

Начинайте с доступа к нужному проекту. Внешняя отправка, расходы, деплой и удаление данных должны соответствовать поручению владельца; уже данное разрешение не нужно запрашивать заново. Название исполнителя в доске не создаёт процесс, не выдаёт доступов и не включает оплату.

При передаче сессии оставляйте в карточке: результат, пути, выполненные проверки, открытые вопросы, текущую задачу и следующий шаг. Почта NameNode хранит сообщения локально; она не будит другого агента. Запуск сессий организуется отдельно.
