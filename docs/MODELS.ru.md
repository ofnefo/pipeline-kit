# Подключение и проверка моделей

Для агента, который настраивает модель под конкретную задачу. Результат — воспроизводимый профиль и отчёт о реальном прогоне, а не только название модели в интерфейсе.

Если сервер и модели ещё не установлены, начните с [AUTO-SETUP](AUTO-SETUP.ru.md): там описаны разведка ресурсов, загрузка выбранных весов, исходный маршрут Ollama и настройка ComfyUI. Модели устанавливаются только для выбранных в опросе задач.

## Разделите два вида настройки

**Модель внешнего агента** выбирается в Codex, Claude Code или другом клиенте. Запишите фактическую модель, доступный режим рассуждения, инструменты и полномочия. Если в задаче Kit задана модель, доска требует совпадения с `--actual-model` при запуске задачи. Это проверка назначения; она не меняет модель текущей сессии.

**Модель Studio** вызывается локальным адаптером Kit. Он работает с текстовыми сообщениями `system`, `user`, `assistant` через HTTP loopback и `/v1/chat/completions`. Он не устанавливает сервер и веса, не передаёт API-ключи и не запускает инструментальные вызовы. Настройки внешнего агента и Studio независимы.

## Подключите один локальный текстовый сервер

1. Выберите сервер и модель под задачу и доступные ресурсы. Проверьте инструкции именно выбранной версии сервера, право использования весов и необходимую RAM/VRAM. Перед запуском посмотрите активные процессы; не занимайте GPU поверх чужой задачи.
2. Установите и запустите сервер отдельной процедурой. Запишите точную команду, версию, PID/владельца, model ID и способ остановки. Сервер должен обслуживать HTTP на loopback и поддерживать потоковые chat completions с завершающим событием `[DONE]`.
3. Скопируйте [workspace.example.json](../config/workspace.example.json) в `<workspace>/config.json`, сохранив существующие настройки, если файл уже есть. В `local_chat` задайте `enabled: true`, точный `model` и `base_url`, например `http://127.0.0.1:8000/v1`. Этот порт — пример; он должен совпадать с вашим сервером.
4. Перезапустите свой экземпляр панели с тем же рабочим каталогом. Откройте Studio и отправьте короткий тестовый запрос.
5. Проверьте появление потокового ответа, завершение сообщения и сохранение чата после перезагрузки страницы. Остановите свой модельный сервер, повторите запрос и убедитесь, что ошибка видна и не выдаётся за успешный ответ. Затем восстановите сервер, если он нужен для работы.

Встроенный адаптер отклоняет удалённые адреса, перенаправления и учётные данные в URL. Он допускает только HTTP loopback; HTTPS endpoint, адрес GPU-сервера в LAN и облачный URL сюда не подходят. Для таких маршрутов нужен отдельно реализованный и проверенный адаптер, а не отключение проверки адреса.

Указанная в списке модель считается настроенной, но это не проверка доступности. Реальный запрос — отдельный обязательный шаг приёмки. В текущем runtime поддерживаются настройки `watch_project_files` и `local_chat` из примера. Произвольные поля в документационных профилях не включают новые возможности.

## Зафиксируйте профиль

Заполните [model-profile.example.json](../config/model-profile.example.json) и храните его рядом с локальными отчётами. Это документационный формат, Kit его не загружает. Запишите:

- точный идентификатор и ревизию модели, источник весов, контрольную сумму при наличии;
- сервер и версию, устройство, квантование, фактически установленные параметры контекста и генерации;
- ограничения входа, формат результата, таймауты и критерии качества для задачи;
- проверенные примеры, время обработки, потребление памяти и известные ошибки.

Подбор роли начинайте с доступной модели, которая решает задачу. Сравнивайте кандидатов на одинаковом наборе примеров. Не повышайте модель автоматически после любой ошибки: сначала отличите нехватку контекста, неправильный путь или неработающий инструмент от недостаточного качества ответа. Переход к платному сервису требует соответствующего поручения владельца.

## Изображения, видео, звук и внешние инструменты

Генеративные маршруты настраиваются отдельно от текстового чата. Для ComfyUI или другого движка сохраняйте экспорт workflow, версии узлов, точные модели и их хеши, входные файлы, seed, разрешение, число кадров/шагов и параметры экспорта. Храните технический профиль отдельно от ключей и пользовательских материалов.

Для каждой интеграции определите:

| Часть | Что проверить |
| --- | --- |
| Вход | Формат, размер, допустимые параметры и место исходников |
| Запуск | Кто владеет задачей, как выдаётся ресурс, как получить job ID |
| Состояние | Как отличить очередь, работу, ошибку, отмену и готовность |
| Результат | Где файл, чем подтверждены его формат, целостность и качество |
| Повтор | Что происходит после таймаута; как избежать дублирования дорогой задачи |
| Остановка | Как отменить только собственную задачу и освободить ресурс |

Если несколько агентов используют один GPU, назначьте общий механизм очереди/резервирования до запуска параллельной работы. Такой планировщик не входит в текущий runtime Kit. Мониторинг сайтов и сервисов — отдельный профиль `site-monitoring` с Uptime Kuma: [выбор и установка](AUTO-SETUP.ru.md#7-мониторинг-и-панель--отдельные-решения). Для него не нужны модели или GPU.

## Проверка качества

Отделяйте четыре результата: сервер запущен; протокол совместим; задача завершилась; качество пригодно. Они не следуют автоматически друг из друга.

Для текста включите обычные задачи, длинный контекст, форматированный результат и недостаточные входные данные. Для изображения проверяйте соответствие брифу, геометрию, читаемость и дефекты. Для видео — ещё стабильность между кадрами, длительность, частоту кадров и звук. Для аудио — разборчивость, произношение, клиппинг, громкость и прослушивание. Метод фиксации результатов — в [TESTING.ru.md](TESTING.ru.md).
