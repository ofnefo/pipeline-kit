# Агент сам собирает рабочую среду

Для агента, которому поручили установить Pipeline Kit. Результат — выбранные пользователем сценарии, установленные скиллы и приложения, настроенные подключения и отчёт о проверке. Выполните установку, а не ограничивайтесь списком рекомендаций.

## 1. Короткий опрос перед установкой

Используйте ответы из разговора. Задайте только оставшиеся вопросы одним сообщением:

1. **Панель управления:** нужны проекты, задачи и NameNode или достаточно инструментов в чате агента?
2. **Работа:** монтаж и звук, графика, документы, веб, 3D? Можно выбрать несколько.
3. **Модели:** нужны локальный текстовый чат, генерация изображений или видео? Монтаж готового видео не требует видеомодели.
4. **Мониторинг:** нужен Uptime Kuma для проверки доступности сайтов и сервисов? Разработка веба сама по себе не включает uptime.
5. **Среда:** на каком компьютере всё должно работать, где хранить проекты и большие модели? Какие редакторы и серверы уже используются?

Не спрашивайте технические сведения, которые можно прочитать самостоятельно. Если пользователь сказал «только задачи и монтаж», это уже ответы: `panel=tasks`, `profiles=[editing]`, без веба, мониторинга, нейрогенерации и текстовой модели. Если панель не нужна, выберите `panel=none`, установите инструменты и скиллы, не запускайте сервер панели.

Покажите выбранный состав одной строкой и продолжайте в пределах поручения. Повторное подтверждение обычной бесплатной установки не нужно. Ввод аккаунта, ключа, системный запрос прав или новые расходы требуют участия владельца только там, где без него нельзя продолжить. Остальные независимые шаги выполняйте дальше.

## 2. Разведка среды

До загрузок сохраните локальный `setup-report.json` вне репозитория:

- ОС и архитектуру, Python, Git, доступный пакетный менеджер и права установки;
- свободное место на дисках программы, данных и моделей, RAM, GPU/VRAM, драйвер и активные задания;
- существующие версии FFmpeg, LibreOffice, Blender, модельных серверов и редакторов, если они нужны выбранным задачам;
- занятые порты, каталоги агентов, существующие правила и установленные скиллы;
- выбранные маршруты, список отсутствующих компонентов, объём загрузок и способ запуска/остановки.

Проверяйте только нужные компоненты. Подходящую существующую установку используйте повторно. Не обновляйте рабочие драйверы и чужие окружения как побочный эффект. У модели учитывайте память контекста и runtime сверх размера весов. Если ресурсов мало, выберите меньшую модель или CPU-маршрут, проверьте время ответа; не записывайте несовместимый маршрут как готовый.

## 3. Скачайте Kit и установите готовые скиллы

Скачайте текущий репозиторий или его выпуск из GitHub; запишите commit SHA. Создайте Python 3.12 окружение по [START-HERE](START-HERE.ru.md). Далее `python` — именно его интерпретатор. Готовые скиллы уже скачаны вместе с Kit: повторная загрузка их из другого источника не нужна.

Например, для задач и монтажа с Codex, из корня Kit:

```text
python tools/setup_skills.py --project /absolute/path/to/project --client codex --panel tasks --profiles editing
python tools/setup_skills.py --project /absolute/path/to/project --client codex --panel tasks --profiles editing --apply
```

Замените путь абсолютным путём рабочего проекта; на Windows, например, `"C:/Work/My project"`. Первая команда только показывает состав. Вторая копирует выбранные скиллы и сверяет хеши. `--client claude` использует `.claude/skills`, `--client both` — оба клиента. `--panel none` не добавляет скиллы управления панелью. Профили можно объединять: `--profiles editing graphics office`. Без `--profiles` и с `--panel tasks` устанавливаются только скиллы управления и ревью.

| Выбор | Готовые скиллы | Что агент устанавливает дополнительно |
| --- | --- | --- |
| `panel=tasks` | `pipeline-control`, `release-review` | Основа Kit; запускает панель, проверяет NameNode и задачи |
| `editing` | `video-editing`, `audio-finishing` | FFmpeg; OTIO только если нужен обмен монтажными проектами |
| `graphics` | `graphic-production` | Основа Kit содержит Pillow; внешний редактор — по задаче |
| `office` | `office-production` | `requirements-office.txt`; LibreOffice/PDF-зависимости при соответствующем экспорте |
| `web` | `web-evidence` | Дополнительный frontend-скилл при создании интерфейсов; браузерные инструменты при проверках |
| `local-chat` | Используются правила текущего агента | Один локальный сервер и одна подходящая текстовая модель |
| `image-generation` | `graphic-production` | ComfyUI, один workflow и требуемые им веса |
| `3d` | Специализированный скилл выбирается отдельно | Blender и контрольная сцена |
| `site-monitoring` | Правила мониторинга задаются отдельно | Uptime Kuma по списку сайтов/сервисов и требованиям уведомлений |

Машиночитаемый состав находится в [setup-profiles.json](../config/setup-profiles.json). Утилита копирует только готовые скиллы; приложения и модели агент устанавливает по следующим разделам. Она не правит глобальные настройки и не заменяет существующие отличающиеся скиллы. При конфликте сравните версии и согласуйте обновление конкретного каталога. Повторный запуск с теми же файлами возвращает `unchanged`.

После копирования объедините проектные правила по [AGENT-SETUP](AGENT-SETUP.ru.md), укажите абсолютный `KIT_ROOT`: скиллы вызывают модули из Kit, копия скилла не включает эти модули. Начните новую сессию клиента и проверьте обнаружение и выполнение выбранного скилла.

Выберите физический каталог: установщик откажет, если в пути есть symlink или junction. При прерванном копировании сравните целевой каталог с исходным скиллом; сохраните свои правки, вынесите неполную копию в резервный каталог вне `.agents/skills`/`.claude/skills` и повторите установку. Существующие отличающиеся файлы автоматически не удаляются. `requirements.txt` — общая основа Kit, даже без запуска панели.

При `panel=none` пропускайте указания скиллов про Studio. Для монтажа используйте из корня Kit `python modules/video/scripts/editorial.py --help` и `python modules/video/scripts/montage.py --help`; выполняйте выбранные команды с проектом и спецификацией по их справке. Проверки видео и звука остаются обязательными.

## 4. Дополнительные готовые скиллы

Для веб-интерфейсов рекомендуемый дополнительный источник — [frontend-design от Anthropic](https://github.com/anthropics/skills/tree/main/skills/frontend-design). Это отдельный маршрут от встроенной растровой композиции. Для других задач сначала проверьте официальный каталог клиента: [OpenAI Skills](https://github.com/openai/skills) и указанные в нём актуальные каталоги плагинов. Не считайте все найденные скиллы обязательными.

Если в Codex есть `skill-installer`, поручите ему установку нужного каталога репозитория в проектный `.agents/skills`, с фиксированным `--ref` и `--dest`. Путь к его скрипту определите в текущей установке, не подставляйте чужой домашний каталог. Синтаксис: `install-skill-from-github.py --repo anthropics/skills --path skills/frontend-design --ref COMMIT_SHA --dest PROJECT_SKILLS_DIR`.

Без установщика агент сам клонирует официальный репозиторий во временный каталог, фиксирует SHA, читает `SKILL.md` и зависимости, затем копирует полный каталог выбранного скилла в проектное место клиента. Сохраните лицензию и источник в локальном отчёте. Не копируйте только один `SKILL.md`, если рядом есть scripts/references/assets. Сначала проверяйте отсутствие конфликта; обновление не должно затирать локальные правки. Проверка установки — новый сеанс агента и реальное маленькое задание. См. [механизм скиллов Codex](https://learn.chatgpt.com/docs/build-skills) и [Claude Code](https://code.claude.com/docs/en/skills).

## 5. Приложения и зависимости

Агент выбирает стабильную версию для обнаруженной ОС, скачивает из официального источника, проверяет опубликованную подпись/хеш при наличии и сохраняет версию и команду установки. На Windows сначала используйте имеющийся WinGet: `winget search`, затем `winget show --id PACKAGE_ID --exact`, проверьте издателя и установите точный ID. На macOS используйте установленный пакетный менеджер или официальный пакет, на Linux — репозиторий дистрибутива или официальный маршрут. Не угадывайте ID пакета и не запускайте все строки таблицы подряд.

| Компонент | Когда нужен и откуда брать | Проверка после установки |
| --- | --- | --- |
| FFmpeg | Монтаж/обработка звука: [официальные варианты загрузки](https://ffmpeg.org/download.html) | `ffmpeg -version`, `ffprobe -version`, короткий экспорт и просмотр/прослушивание |
| LibreOffice | Преобразование Office в PDF: [официальная загрузка](https://www.libreoffice.org/download/) | Версия и преобразование контрольного документа с просмотром PDF |
| Blender | Выбранный 3D-маршрут: [официальная загрузка](https://www.blender.org/download/) | Версия, открытие и сохранение тестовой сцены, контрольный рендер |
| Ollama | Локальный текстовый чат: [Windows](https://docs.ollama.com/windows), [Linux](https://docs.ollama.com/linux), [macOS](https://docs.ollama.com/macos) | Версия, список моделей, реальный потоковый запрос через Kit |
| ComfyUI | Генерация: [официальная установка](https://docs.comfy.org/installation/manual_install) | Workflow с сохранённым изображением, проверка содержимого |

Python-зависимости ставьте в окружение Kit: `python -m pip install -r requirements-office.txt`, `requirements-pdf.txt` или `requirements-editorial.txt` только для выбранного сценария; после установки — `python -m pip check`. ComfyUI и другие GPU-стеки размещайте в отдельных окружениях по их требованиям к Python/PyTorch. Не ставьте их зависимости в окружение панели.

После установки обновите PATH только нужного процесса или используйте абсолютный путь. Фоновым процессам назначьте владельца и лог; не создавайте всплывающие консоли. Автозапуск, срок хранения резервных копий и расписание настраивайте по выбранному режиму эксплуатации. Если доступен только интерактивный установщик, завершите поддерживаемые шаги и запросите конкретное действие пользователя, затем продолжите.

## 6. Скачайте и подключите выбранные модели

**Текстовый чат.** Сначала используйте подходящий существующий сервер. Для новой установки один понятный исходный вариант — Ollama и [Qwen3 4B](https://ollama.com/library/qwen3:4b). Это кандидат для проверки, а не универсальная лучшая модель. На странице указан размер весов около 2,5 GB; реальная память больше и зависит от контекста. Проверьте ресурсы перед загрузкой. Следуя [CLI Ollama](https://docs.ollama.com/cli), выполните:

```text
ollama --version
ollama list
ollama pull qwen3:4b
ollama show qwen3:4b
```

Если подходящий сервер уже обслуживает порт 11434, используйте его; не запускайте второй. Иначе запустите свой сервер по инструкции ОС. Сохраните digest модели и параметры. В существующем `<workspace>/config.json` объедините, сохранив остальные поля:

```json
{"local_chat": {"enabled": true, "base_url": "http://127.0.0.1:11434/v1", "model": "qwen3:4b"}}
```

Локальный [OpenAI-совместимый API Ollama](https://docs.ollama.com/api/openai-compatibility) подходит как маршрут для проверки адаптера Kit. Выполните реальный запрос из Studio: непустой текст, завершение потока, сохранение чата и видимая ошибка недоступности сервера. Только после этого поставьте `pass`. Не выбирайте cloud-модели вместо локальных молча. Без панели проверьте модель через выбранный клиент; Studio и его config тогда не нужны.

**Изображения.** Установите ComfyUI по его требованиям, откройте [официальные шаблоны workflow](https://github.com/Comfy-Org/workflow_templates), выберите один под задачу и устройство. Возможный исходный кандидат — [SDXL Base 1.0](https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0); проверьте требования workflow, лицензию и доступную память. Агент скачивает конкретные файлы весов по официальным ссылкам выбранного workflow, фиксирует ревизию/хеш и помещает их в предусмотренные категории models. Не скачивайте весь репозиторий со всеми форматами весов. Если нужные веса уже есть, подключите их штатным механизмом путей ComfyUI. Проверьте один результат и сохраните workflow, seed и настройки.

**Видео и другие модели.** Подбор начинается с задачи, длительности, формата и ресурсов, затем — официальный workflow, точные веса, установка и контрольный результат. Профиль `editing` не запускает эту процедуру. Для неподдерживаемого готовым Kit маршрута агент настраивает отдельный инструмент/CLI; интеграция кнопки панели требует отдельного адаптера и его проверки. Рабочая генерация в ComfyUI не означает, что кнопка Kit уже умеет её запускать.

## 7. Мониторинг и панель — отдельные решения

При `panel=tasks` разверните локальную панель по START-HERE и проверьте проекты, задачи и NameNode. Для монтажа добавьте FFmpeg и скиллы профиля `editing`. Не устанавливайте веб-стек, браузерную автоматизацию, uptime-сервис или модели, если они не выбраны.

Профиль `site-monitoring` выбирает **Uptime Kuma**. Он независим от веб-разработки и панели Kit: можно установить его без панели или оставить выключенным при работе с задачами и монтажом. Готового адаптера Kuma в панели Kit нет; агент разворачивает отдельную службу и сохраняет её адрес в локальном отчёте.

1. Уточните только отсутствующие параметры: сайты/сервисы, тип и частоту проверок, компьютер службы, адресатов уведомлений. Для круглосуточного мониторинга нужен постоянно работающий компьютер. Если Kuma уже установлен, используйте его, сохраняя существующие проверки.
2. Установите недостающие компоненты по [официальной инструкции Uptime Kuma](https://github.com/louislam/uptime-kuma#-how-to-install). Выберите Docker или поддерживаемую установку без Docker по результатам разведки. Перед запуском проверьте свободный порт, сохраните версию/ревизию или digest образа. Для локальной установки привяжите интерфейс к `127.0.0.1`; сетевой доступ настройте только для выбранного пользователем режима.
3. Выделите постоянный локальный каталог или Docker volume для данных (`/app/data` в контейнере). Запишите расположение данных, команды запуска/остановки и режим автозапуска. Подготовьте резервное копирование и восстановление в отдельную тестовую среду; обновление существующей установки выполняйте по [официальному порядку обновления](https://github.com/louislam/uptime-kuma/wiki/%F0%9F%86%99-How-to-Update).
4. Настройте учётную запись владельца и выбранные мониторы. Подключите только указанные каналы уведомлений; секреты вводит владелец. Без адресата оставьте локальный обзор и отметьте уведомления как не настроенные. Тестовое сообщение отправляйте только явно согласованному адресату.
5. На отдельной тестовой цели проверьте переход доступен → недоступен → восстановлен, историю состояния и выбранные уведомления. Не останавливайте рабочие сайты ради проверки. Сохраните результат и путь к резервной копии; доступность страницы Kuma сама по себе не подтверждает работу мониторинга.

Профили определяют состав установки и проверки. Они не скрывают разделы текущего интерфейса и не являются системой прав. Невыбранные интеграции остаются неподключёнными; отдельная настройка меню — задача интерфейса.

## 8. Закончите проверенной установкой

Для каждого выбранного маршрута пройдите [TESTING](TESTING.ru.md): запуск, реальное действие, результат, ошибка и восстановление. Для `panel=none` проверки панели/NameNode получают `not_selected`; проверьте CLI, скиллы и файлы выбранных инструментов. Не устанавливайте Office и Playwright только ради полного набора тестов, если пользователь выбрал исключительно монтаж: выполните относящиеся к установленным компонентам проверки, остальные обозначьте как невыбранные.

Итоговый отчёт: ответы опроса, выбранные/невыбранные функции, установленные версии и источники, хеши скиллов/моделей, настройки без секретов, команды запуска/остановки, контрольные результаты, резервная копия и восстановление. Разделяйте `installed`, `configured`, `verified` и `blocked`. При блокере продолжите независимые части и укажите точное недостающее действие. Не завершайте поручение одной инструкцией, если агент имеет доступ и может выполнить установку сам.
