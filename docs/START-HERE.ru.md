# Развернуть Pipeline Kit с помощью агента

Для владельца рабочей среды и агента, который настраивает её впервые. Результат — работающая локальная панель, карта проектов, правила агентов и проверенные подключения выбранных инструментов.

При установке агентом начните с [опроса и автоматической настройки](AUTO-SETUP.ru.md): там выбираются панель и рабочие направления, готовые скиллы, приложения и модели. Ниже — базовый маршрут с панелью. Если выбраны только инструменты без панели, пропустите её запуск, NameNode и доску; зависимости и проверки выбирайте по своему профилю.

## Что выбрать перед установкой

Запишите ответы в локальный файл `deployment-notes.md` вне репозитория:

| Параметр | Что указать |
| --- | --- |
| Компьютер | ОС, версия Python, доступная память, GPU при необходимости |
| Каталог программы | Абсолютный путь к Pipeline Kit |
| Рабочий каталог | Отдельный обычный локальный каталог для проектов и состояния |
| Агент | Codex, Claude Code или другой агент с доступом к файлам и командной строке |
| Задачи | Например: графика и документы; видео; разработка |
| Дополнительные инструменты | Только необходимые для выбранных задач |
| Модели | Существующий локальный сервер или отдельная задача по его установке |
| Приёмка | Какие сценарии должны работать после настройки |

Если владелец уже указал параметры, используйте их. Уточните только то, без чего нельзя выбрать каталог, полномочия или платный сервис. Не устанавливайте все инструменты заранее.

## 1. Установите основу

Используйте Python 3.12. Склонируйте этот репозиторий или распакуйте его архив и откройте терминал в корне программы. Рядом должно быть место для отдельной папки данных. Ниже команды для PowerShell; выполняйте их по одной и останавливайтесь при ошибке.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe pipeline_kit.py --workspace ..\pipeline-workspace init
.\.venv\Scripts\python.exe pipeline_kit.py --workspace ..\pipeline-workspace doctor
.\.venv\Scripts\python.exe pipeline_kit.py --workspace ..\pipeline-workspace serve
```

Откройте `http://127.0.0.1:8770`. Команда `serve` работает в текущем терминале; `Ctrl+C` останавливает этот экземпляр панели. Если порт занят, выясните владельца процесса. Не завершайте чужой процесс. Для первого развёртывания используйте порт 8770: некоторые клиентские ссылки рассчитаны на него.

На macOS/Linux путь к Python окружения — `.venv/bin/python`, пути записываются через `/`. Проверенное исходное окружение — Windows/Python 3.12; успешную установку на другой ОС фиксируйте своим отчётом, а не ссылкой на Windows-проверку.

Программа и рабочие данные должны лежать отдельно. Рабочий каталог содержит проекты, базы, карточки и чаты. Не используйте для него symlink/junction или каталог облачной синхронизации с reparse points. Все агенты и панель должны указывать на один и тот же абсолютный путь.

## 2. Подключите агента

Пройдите [настройку агентов и скиллов](AGENT-SETUP.ru.md). Установите проектные правила, укажите путь к Kit и рабочему каталогу, задайте постоянный идентификатор сессии. Проверьте в новой сессии, что агент прочитал правила и может назвать доступные скиллы.

Готовое задание для первого запуска — [BOOTSTRAP_PROMPT.ru.md](../agents/BOOTSTRAP_PROMPT.ru.md). Оно помогает развернуть среду по этим документам; само по себе не запускает установщик.

## 3. Создайте карту проектов и первую задачу

В панели создайте тестовый проект. Проверьте его карточку, расположение файлов и правила работы. Затем пройдите [сценарий NameNode и доски задач](NAMENODE.ru.md). Карточка описывает проект, а задача — конкретный результат внутри него.

## 4. Выберите производственный маршрут

| Задача | Скилл | Инструменты |
| --- | --- | --- |
| Работа с панелью и проектами | `pipeline-control` | Основная установка |
| Графика, контактные листы, подготовка к печати | `graphic-production` | Pillow входит в основную установку |
| Документы, расчёты, реестры | `office-production` | `requirements-office.txt`; для отдельных операций PDF/LibreOffice |
| Монтаж и экспорт видео | `video-editing` | FFmpeg и ffprobe; OTIO по необходимости |
| Обработка звука | `audio-finishing` | FFmpeg и ffprobe |
| Проверка сохранённого HTML | `web-evidence` | Основная установка |
| Проверка изменений и выпуск | `release-review` | Проверки по фактическому изменению |

Команды и зависимости перечислены в [MODULES.md](MODULES.md). После установки внешнего инструмента повторите `doctor` и выполните маленькую реальную задачу. Обнаруженный исполняемый файл ещё не означает, что весь маршрут проверен.

## 5. Подключите модели и дополнительные системы

Следуйте [методике подключения моделей](MODELS.ru.md). Начните с одного нужного подключения. Studio поддерживает локальный текстовый чат через OpenAI-совместимый HTTP-сервер. Генерация изображений и видео, редакторы, мониторинг и удалённые исполнители требуют отдельных интеграций.

Для каждой такой интеграции запишите: назначение, установленную версию, входы и выходы, способ запуска и остановки, владельца процесса, доступы, контрольный пример и путь к отчёту. Не обозначайте интеграцию как работающую, пока не получили результат именно через неё. Ответ API `501` означает, что адаптер ещё не реализован.

## 6. Примите установку

Пройдите [проверки и критерии готовности](TESTING.ru.md). Сохраните отчёт рядом с локальными данными, используя [шаблон](../config/acceptance-receipt.example.json). Базовую установку и дополнительные возможности принимайте отдельно. Необязательный, невыбранный компонент получает статус `not_selected`; выбранный, но ещё не проверенный — `not_run` или `blocked`.

## 7. Обновляйте и сохраняйте данные

1. Завершите активные задания и остановите свой экземпляр панели.
2. Скопируйте рабочий каталог целиком в отдельный каталог резервных копий. Сохраните версию Kit и список зависимостей.
3. Восстановите копию в новый локальный каталог и проверьте карточки, задачи и файлы. Только после этого считайте резервную копию проверенной.
4. Установите новую версию программы в отдельный каталог. Сначала испытайте её на восстановленной копии данных.
5. После успешной проверки переключите запуск на новую версию и основной рабочий каталог. При ошибке верните старую программу; если формат данных изменился, восстановите согласованную с ней копию после остановки панели.

Периодические копии настраиваются средствами вашей ОС. Укажите расписание, способ остановки или согласованного снимка, каталог назначения, срок хранения и проверку восстановления. Kit сам не устанавливает планировщик резервных копий. Обновления общих инструментов готовьте по [процедуре выпуска](RELEASE.md).

## Если что-то не работает

| Симптом | Следующее действие |
| --- | --- |
| Панель не открывается | Проверьте вывод `serve`, Python окружения и занятость порта |
| Агент не видит задачи | Сравните абсолютный `PIPELINE_KIT_WORKSPACE` с `--workspace` панели |
| NameNode вернул `busy` | Прочитайте владельца claim, согласуйте передачу; не включайте `force` автоматически |
| Изменение задачи отклонено | Снова получите задачу, прочитайте её новую версию и владельца |
| Модель видна, но не отвечает | Проверьте реально запущенный сервер, точный model ID и потоковый протокол |
| API вернул `501` | Зарегистрируйте недостающий адаптер как отдельную задачу |
| Скилл не обнаружен | Проверьте проектный каталог скиллов и начните новую сессию агента |
