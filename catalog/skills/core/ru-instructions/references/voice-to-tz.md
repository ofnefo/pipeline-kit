# Голосовые → ТЗ, баг-лист и вопросы

Задача — превратить речь в рабочий документ, а не в пересказ. Пересказ, наблюдения и «что автор на
самом деле имел в виду» не нужны, если об этом не просили.

## 1. Расшифровка (локально)

Одиночные голосовые и короткие записи — локальной моделью распознавания речи (speech-to-text) с языком `ru`.
Пример с открытым Whisper CLI:

```
whisper <файл> --language ru --model large-v3-turbo --output_format txt
```

- Для русского хорошо работают Whisper large-v3 / large-v3-turbo и специализированные русские модели
  (например GigaAM); короткие записи — русская модель, длинные и смешанные языки — Whisper.
- Пословные таймкоды включать, если нужно ссылаться на минуту записи; иначе — только текст.
- STT на CPU не требует очереди GPU; на GPU — одна тяжёлая задача за раз.

Совещания, созвоны, несколько говорящих — расшифровка с разметкой спикеров (диаризация, например
pyannote поверх Whisper); результат остаётся внутри папки проекта.

Облачные сервисы распознавания — только если оператор прямо попросил облако для этой работы.

## 2. Хранение и приватность

```
<проект>/private/voice/          # исходные голосовые (если их вообще нужно хранить)
<проект>/private/transcripts/    # расшифровки: <дата>_<n>_transcript.txt, в шапке — исходный файл и длительность
<проект>/docs/tz/                # ТЗ, баг-лист, вопросы — рабочие документы
```

- Голосовые и расшифровки — приватные: не коммитить (папки `private/` и `meeting-transcripts/` в
  `.gitignore`), не отправлять в каналы выдачи, не вставлять целиком в чаты и брифы других агентов.
- В ТЗ — только выжатые требования со ссылкой на источник («голосовое 3, 02:15»), не куски речи.
- Имена папок — пример; брать из структуры проекта.

## 3. Слияние

1. Прочитать все расшифровки серии целиком до начала записи.
2. Разметить фрагменты: требование, баг, вопрос, контекст/мотивация, решение, мусор (повторы, оговорки, «эээ»).
3. Совпадающие пункты из разных голосовых объединить в один, указав все источники.
4. Противоречия («сначала синий, потом — нет, лучше зелёный») — последняя версия становится требованием,
   если автор явно передумал; если неясно — вопрос. Отменённое — в историю изменений, не удалять молча.
5. Ошибки распознавания (странные слова, имена, числа) — сверить по контексту; если не уверен — пометить
   «(STT: «…», проверить)» и вынести в вопросы.

## 4. Что выдать

```
# ТЗ: <что> — по голосовым <от кого>, <даты>
Источник: расшифровки локальной STT-модели, N голосовых, общая длительность ММ:СС.

## Цель
<1–3 предложения: зачем и для кого — как сказал автор>

## Требования
Т-1. <проверяемое требование>. Приоритет: обязательно. Источник: гс 1, 00:40. Зависит от: —
Т-2. … Зависит от: Т-1, В-2

## Баги
Б-1. <что не так> — как проявляется — к чему приводит. Источник: гс 2, 01:10

## Вопросы
В-1. <вопрос>? Кому: автору. Блокирует: Т-2. Варианты, если есть: а) … б) …

## Числа и имена из голосовых
<все числа, сроки, суммы, имена, названия — как сказаны, с источником>

## Вне рамок / отложено
<что автор упомянул, но не просил сейчас>
```

Правила:
- Номера стабильны: Т-3 остаётся Т-3 во всех версиях. Удалённое — «Т-3 (снято в v2: …)».
- У каждого пункта — источник. Пункт без источника — это выдумка; его не должно быть.
- Числа, суммы, сроки, имена, названия сущностей — без округления и без «примерно», если автор сказал точно.
- Причинно-следственные связи сохранять: «потому что клиенты не доходят до оплаты» — часть требования.
- Метрики разделять: цель, текущее значение, целевое значение, где показывать, зачем.

Форматы по запросу:
- **Коротко** (для мессенджера): 3–8 строк, только пункты, без вступления.
- **Подробно** (для баг-репорта и подрядчика): каждый пункт — проявление и последствие.
- По просьбе «разверни» — раскрыть те же пункты, не менять структуру.

## 5. Новые голосовые в той же серии

- Обрабатывать как дополнение к существующему документу: новая версия v2, v3…
- В начале — блок «Что изменилось в vN»: добавлено (Т-7, Б-4), изменено (Т-2: срок с пятницы на среду),
  снято (Т-3), закрыты вопросы (В-1 → ответ).
- Отвечённые вопросы превращаются в требования или правки с источником «ответ на В-1, гс 5».

## 6. Честность

- Писать, с чем работали: «по расшифровкам STT» — не «прослушал(а)».
- Если часть записи не распознана или обрезана — указать где и что это может значить.
- Если спросили «ты точно всё учёл?» — перечислить по голосовым, что из каждого вошло в документ.

## 7. Проверка перед выдачей

- [ ] Все голосовые серии учтены, у каждого пункта — источник.
- [ ] Нет требований, которых не было в речи; допущения — в вопросах.
- [ ] Числа и имена совпадают с расшифровкой; сомнительные места STT помечены.
- [ ] Зависимости между Т, Б и В указаны.
- [ ] Приватные материалы не вышли за пределы проекта.
