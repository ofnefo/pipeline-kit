# Ударения, ё, омографы и словарь проекта

## Ё

- Ставить ё во всём clean-тексте и в TTS-файле. Это не стилистика, а подсказка ударения: в слове с ё
  ударение почти всегда на ё («всё», «ещё», «Королёв», «приём»).
- Исключение — сложные слова и заимствования, где ё безударная («трёхэтажный» читается нормально,
  но ударение там не на ё) — их проверять на слух.
- Пары, где ё меняет смысл: все/всё, небо/нёбо, лет/лёт, совершенный/совершённый, узнаем/узнаём.
- Имена с ё: Пётр, Семён, Фёдор, Артём, Алёна; фамилии — по документу человека (Королёв, но Хрущёв/Хрущев —
  как в источнике мероприятия). Не знаем — вопрос.

## Омографы

Омограф — одинаковое написание, разное ударение и смысл. Движок выбирает вариант сам и часто ошибается.

| Слово | Варианты | Как снять без знаков |
|---|---|---|
| замок | за́мок (крепость) / замо́к (дверной) | «старинный замок» / «дверной замок», «замочек» |
| мука | му́ка (страдание) / мука́ (мелко молотое зерно) | «мучение» / «пшеничная мука» |
| стоит | сто́ит (цена) / стои́т (стоять) | «стоит пятьсот рублей» обычно читается верно; иначе «обойдётся в…» |
| глаза | гла́за (род. ед.) / глаза́ (мн.) | «из глаза» / «глаза», перестроить фразу |
| самого | само́го / са́мого | по смыслу: «самого главного» / «его самого» — проверить на слух |
| атлас | а́тлас (книга карт) / атла́с (ткань) | «атлас дорог» / «атласная ткань» |
| орган | о́рган / орга́н | «орган власти» / «играет на органе» — проверить |
| писать | пи́сать / писа́ть | избегать двусмысленных мест |
| уже | уже́ (наречие) / у́же (сравн. от «узкий») | «уже» как наречие почти всегда верно; «у́же» → «более узкий» |
| дорога | доро́га / дорога́ (кр. прил.) | «дорогая» вместо «дорога» в смысле цены |
| часа | часа́ (два часа) / ча́са (около часа) | проверять по слуху в каждом месте с временем |
| ведение / видение, хаос, творог, договор, звонит | нормативное ударение | следить, чтобы движок не читал просторечно |

Правило поиска (из практики больших аудиокниг): найти слово во всех формах и падежах по всему
сценарию, включая места без пометок, и решать каждое вхождение по контексту. Одна правка по
первому месту без проверки остальных — частая причина «половина мест исправлена».

## Движки и знаки ударения

Наблюдения по токенизаторам двух открытых движков (проверено на уровне токенов, не на звук):

| | Qwen3-TTS (релиз, Apache-2.0) | XTTS-v2 (только черновики, CPML) |
|---|---|---|
| ё | Сохраняется как отдельный токен | Есть в словаре, сохранять |
| `+` перед ударной гласной | Доходит до модели отдельным токеном; влияние на звук — **не проверено** | Превращается в `[UNK]` — **удалить** |
| Знак ударения U+0301 (а́) | Доходит отдельным токеном; влияние — **не проверено** | `[UNK]` — **удалить** |
| Цифры | Нормализации нет, текст идёт в модель как есть — писать словами | Свой разворот чисел есть, но писать словами всё равно (одинаковый текст для обоих) |
| Символы %, &, @, № | Не нормализуются — заменить словами | Частично заменяет сам; заменить словами |

Для другого движка повторить ту же проверку токенизатора, прежде чем доверять знакам ударения.

## Стратегии исправления, по порядку

1. **context** — добавить или поменять соседнее слово, которое снимает двусмысленность.
2. **rephrase** — заменить слово синонимом или перестроить фразу (в clean не трогать смысл; если
   замена меняет смысл — согласовать с автором текста).
3. **yo** — поставить ё, если её не хватало.
4. **respell** — фонетическая запись только в TTS-файле: «Энвидиа», «эф-эс-бэ», «Мак-Ги».
5. **split** — разбить фразу на два сегмента, чтобы слово оказалось в конце (там чётче) или в начале.
6. **plus** — `+` перед ударной гласной (`зам+ок`). Для XTTS-v2 запрещено (токен `[UNK]`). Для Qwen3-TTS —
   только после A/B: два рендера с одинаковым seed, со знаком и без; если md5 файлов совпали —
   знак проигнорирован; если различаются — слушать, какой правильный.
7. **acute** — знак U+0301 после ударной гласной (`замо́к`). Та же проверка, что для `+`. Для XTTS-v2 запрещено.

В обоих движках `+` и U+0301 — **не проверено** на звук: что они не ломают текст, проверено только для
токенизатора. Решения, найденные на одном голосе (референсе), на другом голосе перепроверять.

Числительные после перевода в слова — отдельная зона риска: «восьмидесяти», «четырёхсот», «пятьюдесятью».
Имена в косвенных падежах — ударение как в именительном, если это не противоречит норме.

## Формат `stress-dictionary.json`

Лежит в папке проекта рядом со сценарием (`<project>/<папка сценария>/stress-dictionary.json`). Один на проект.
JSON без комментариев; описание полей — таблица ниже.

```json
{
  "schema": "ru-voiceover/stress-dictionary@1",
  "project": "<slug>",
  "updated": "2026-10-04",
  "default_engine": "qwen3-tts",
  "entries": [
    {
      "id": "zamok-door",
      "clean": "замок",
      "stress": "зам+ок",
      "forms": {"замка": "замк+а", "замки": "замк+и"},
      "kind": "homograph",
      "context": "дверной замок на входе в зал",
      "scope": "all",
      "status": "active",
      "tts": {
        "qwen3-tts": {"text": "дверной замок", "method": "context", "verified": "2026-10-04",
                       "take": "40-vocals/vo-v003.segments/012.wav", "result": "ok"},
        "xtts-v2": {"text": "дверной замок", "method": "context", "result": "untested"}
      },
      "source": "сценарий v2, сегмент 012",
      "note": ""
    }
  ]
}
```

| Поле | Обязательно | Значение |
|---|---|---|
| `schema` | да | Всегда `ru-voiceover/stress-dictionary@1` |
| `project` | да | Слаг проекта |
| `updated` | да | Дата последней правки, ГГГГ-ММ-ДД |
| `default_engine` | да | `qwen3-tts` или `xtts-v2` |
| `entries[].id` | да | Латиница через дефис, стабильный, не переиспользуется |
| `clean` | да | Как слово пишется в clean-тексте (с ё) |
| `stress` | да | Та же форма с `+` перед ударной гласной — нотация, совместимая с `custom_dict` у ruaccent |
| `forms` | нет | Другие формы слова: clean → со знаком `+` |
| `kind` | да | `name`, `org`, `place`, `brand`, `abbr`, `foreign`, `homograph`, `term`, `number` |
| `context` | для омографов | Фраза или смысл, при котором действует запись |
| `scope` | да | `all` или список id сегментов, например `["012","031"]` |
| `status` | да | `proposed` (ждёт подтверждения), `active`, `revoked` |
| `tts.<движок>.text` | да | Что именно подставляется в TTS-файл |
| `tts.<движок>.method` | да | `plain`, `yo`, `context`, `rephrase`, `respell`, `split`, `plus`, `acute` |
| `tts.<движок>.verified` | нет | Дата прослушивания |
| `tts.<движок>.take` | нет | Относительный путь к дублю, на котором проверено |
| `tts.<движок>.result` | да | `ok`, `fail`, `untested` |
| `source` | да | Откуда решение: «организатор, письмо от 03.10», «сам спикер на видео», «словарь ударений» |
| `note` | нет | Свободный комментарий; для `revoked` — причина отмены |

Правила ведения:
- Записи не удаляют. Отменённое решение — `status: "revoked"` и причина в `note`; так видно, что уже пробовали.
- `proposed` → `active` только после подтверждения (оператор, заказчик, организатор) или удачного прослушивания.
- Применение к сценарию — как предложение: таблица «сегмент — было — станет — запись словаря», потом правка TTS-файла.
- Пути в словаре — относительные, внутри проекта. Никаких личных путей, контактов и ключей.
- `stress` можно выгрузить в формат `custom_dict` для ruaccent (`{"замок": "зам+ок"}`), но сам ruaccent
  запускается только по решению оператора: при первом запуске он скачивает модели.
- Слова, проверенные в нескольких проектах, можно предложить в общий словарь команды — не переносить молча.
