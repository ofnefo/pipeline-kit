# Сценарий, рендер и петля «послушал — поправил»

## Папки и имена

Внутри проекта, куда пойдёт звук, — как принято в его правилах. Типично:

```
<PROJECT_ROOT>/
  20-text/
    vo.clean.md              # чистый текст для людей
    vo.tts.json              # текст для движка, сегменты с id
    stress-dictionary.json   # словарь ударений проекта
    vo.questions.md          # вопросы по произношению (имена, бренды, залы)
    vo.listen-notes.md       # заметки прослушивания по версиям
  40-vocals/
    vo-v001.wav              # результат рендера
    vo-v001.segments/        # по файлу на сегмент
    vo-v001.json             # сайдкар с QA
```

Имена папок `20-text` и `40-vocals` — пример; брать из структуры конкретного проекта.

## Форматы TTS-файла

JSON (предпочтительно — есть id и паузы):

```json
{"segments": [
  {"id": "001", "text": "Добрый вечер.", "pause_after": 0.6},
  {"id": "002", "text": "Мы начинаем через пять минут.", "start": 2.0, "end": 4.5},
  {"id": "003", "text": "Просим гостей пройти в третий зал."}
]}
```

- `text` — обязательно; `start`/`end` — секунды, если озвучка ложится на монтаж; `pause_after` — пауза после сегмента.
- TXT: одна строка — один сегмент; можно префикс `[mm:ss.s]` или `[mm:ss.s-mm:ss.s]`; строки с `#` — комментарии.
- SRT — удобно, если субтитры уже есть.

Какие из этих форматов принимает ваша обёртка над TTS — проверить по её `--help`; если она понимает
только TXT, держите JSON как исходник и выводите из него TXT.

Один сегмент — одна-две фразы на вдох, примерно до 20 секунд звука. Длинные сегменты чаще
«плывут» и съедают слова.

## Рендер (только если задача прямо его включает)

Локальный движок, например Qwen3-TTS для релиза. Что должна уметь обёртка (своя или из пайплайна):

- **клонирование по одному референсу** (`ref-audio` + его точный текст) — один голос на весь сценарий.
  Режим «голос по описанию» меняет тембр от фразы к фразе — для диктора не годится;
- **пакетный режим** по TTS-файлу: каждый сегмент — отдельная генерация, склейка с паузами
  (`pause_after` или общий зазор, разумный дефолт — 0,35 с);
- **фиксированный seed** и запись в сайдкар: seed, референс, версия движка, словарь;
- **без перезаписи**: каждая итерация — новая версия `vNNN`, затирание только явным флагом;
- **права на голос**: клон — только при подтверждённых правах (свой, лицензированный или синтетический голос),
  отметка в сайдкаре;
- **подгонка под слот** (дубляж, закадр под монтаж): если фраза не помещается в окно таймкода — ускорить
  сегмент без смены высоты тона до разумного предела (порядка 1,25×), остаток сдвинуть и записать drift.
  Если и предела не хватает — сокращать текст, а не поднимать предел;
- **финальная обработка под место**: речь, видео, стриминг, эфир — свои целевые уровни громкости.

Практика:
- Одиночная фраза для A/B — тот же движок, тот же seed и референс, текст одной строкой.
- Тяжёлая GPU-задача — одна за раз: взять блокировку GPU проекта, если она занята — ждать, не обходить.
- Порядок скорости на локальном GPU — секунды-десятки секунд на фразу; оценить время всего батча до запуска.
- XTTS-v2 — только черновики (лицензия CPML некоммерческая). Не изобретать для него запуск: брать ту
  обёртку, что описана в правилах вашего пайплайна.

## Автоматический QA

После батча каждый сегмент прогоняется через локальную модель распознавания речи (например Whisper
или другая STT с хорошим русским), результат пишется в сайдкар `.json`:
- WER по сегменту; разумный порог — 0,15: выше значит слово съедено, заменено или прочитано не так;
- длительность против окна из таймкодов и наложения сегментов (drift);
- строка в журнал рендеров проекта (например `renders.jsonl`).

Что QA ловит и чего не ловит:

| Ловит | Не ловит |
|---|---|
| Пропущенные и лишние слова, проглоченные числа | Неверное ударение (STT «слышит» слово правильно) |
| Латиница или аббревиатура, прочитанная мусором | Интонацию, эмоцию, темп |
| Переполнение окна по времени | Омограф, прочитанный во втором смысле |

Поэтому после QA обязательно прослушивание ушами: оператор, заказчик или тот, кто знает имена.

## Петля «послушал — поправил»

1. Рендер `vNNN` (по задаче). Записать в `vo.listen-notes.md`: версия, seed, референс, дата, движок.
2. Открыть сайдкар: сегменты с WER > 0,15 и drift — первые кандидаты.
3. Прослушать всё. Заметки строго в формате: `seg-id: слово — как прозвучало → как надо`.
   Пример: `014: Королёв — «Королев» без ё → поставить ё` или `022: МГУ — «мгу» одним словом → «эм-гэ-у»`.
4. Для каждой заметки найти слово во всех формах по всему сценарию, а не только в этом сегменте.
5. Выбрать стратегию по порядку из `stress-dictionary.md`, записать решение в словарь (`proposed`).
6. Править только TTS-файл. Если пришлось менять смысл — сначала clean, потом заново TTS.
7. Перерендерить только изменённые сегменты, если обёртка позволяет; иначе — весь батч, `vNNN+1`,
   тот же seed и референс, чтобы разница была только в тексте.
8. Сравнить: md5 одинаковый у сегмента со знаком и без — знак не работает на этом движке, вернуть
   другую стратегию. Разный — слушать.
9. Удачные записи словаря → `active`, `result: ok`, путь к дублю. Неудачные → `fail`, следующая стратегия.
10. Когда все сегменты прошли QA и прослушивание — зафиксировать канон: версия, seed, референс, md5
    словаря. Дальнейшие правки — только через новую версию.
11. Изменился текст — сдвинулся тайминг: субтитры и монтаж пересинхронизировать.
12. Готовый файл после QA — передать через канал выдачи проекта после одобрения оператора, с receipt
    (путь + хэш). Промежуточные дубли и сегменты не отправлять.

## Ручная проверка STT одного файла

Прогнать файл через ту же локальную STT-модель с языком `ru` и сравнить с текстом сегмента. Пример
с открытым Whisper CLI: `whisper <файл.wav> --language ru --model large-v3 --output_format txt`.
STT на CPU не требует блокировки GPU; на GPU — по общей очереди.

## Что сказать в отчёте

- Пути: clean, TTS-файл, словарь, вопросы, заметки прослушивания.
- Если был рендер — путь к `vNNN.wav` и сайдкару, код выхода, средний и максимальный WER, сегменты выше порога.
- Если рендера не было — так и написать: «текст подготовлен, рендер не запускался».
- Открытые вопросы по произношению — списком с id сегментов.
