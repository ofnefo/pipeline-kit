# Технический чек-лист: сначала Яндекс, потом Google

База — собственная практика SEO-аудита и перечень проверок
Horosheff/google-yandex-seo-skill (MIT). Статусы в аудите: OK / WARN / FAIL / N/A.
Приоритет: P1 — мешает индексации или даёт дубли; P2 — теряем сниппет/доверие; P3 — улучшение.

## 1. Вебмастер и Search Console (P1)

| Шаг | Яндекс Вебмастер | Google Search Console |
|---|---|---|
| Подтверждение прав | meta `yandex-verification`, HTML-файл или DNS TXT | meta `google-site-verification`, HTML-файл или DNS TXT (доменный ресурс — только DNS) |
| Sitemap | добавить URL sitemap | добавить URL sitemap |
| Главное зеркало | указать (обычно `https://apex`) | — (работают 301 и canonical) |
| Регион | указать регион сайта | — |
| IndexNow | включить, положить ключ | Google IndexNow не поддерживает |

ID и коды вводит владелец сайта. Агент готовит место (`<meta name="yandex-verification" content="[ID от владельца]">`)
и говорит, в какой файл/шаблон его вписать. В чат значения не выводятся.

## 2. Зеркала и редиректы (P1)

- `http://`, `www.`, `http://www.` → **один** 301 на главный адрес (по умолчанию `https://<домен>/`).
- Без цепочек (http → www → https): каждый вариант сразу на финальный адрес.
- Директиву `Host:` в robots.txt удалить — устарела (с 2018 года), главное зеркало задают 301 и Вебмастер.
- Старые и редиректные домены — 301 с сохранением пути.
- Шаблон nginx (только с одобрения владельца сайта, деплой — по его явной просьбе для сайта):
  `server_name www.<домен>; return 301 https://<домен>$request_uri;`, `charset utf-8;`, `error_page 404 /404.html;`.

## 3. robots.txt (P1)

```
User-agent: *
Disallow: /admin
Disallow: /app/login
Clean-param: utm_source&utm_medium&utm_campaign&utm_content&utm_term&yclid&gclid&fbclid /

Sitemap: https://<домен>/sitemap.xml
```
- `Sitemap:` — абсолютный URL. `Clean-param` понимает Яндекс; Google его игнорирует — для него canonical.
- Закрывать служебное: админку, вход, поиск по сайту, корзину, фильтры-дубли, dev-пути.
- **Не** закрывать CSS, JS, картинки, шрифты.
- Блок ИИ-ботов — `geo-ai.md`. Важно: бот с собственной группой `User-agent` не читает группу `*`,
  поэтому служебные `Disallow` надо повторить в каждой именованной группе с `Allow`.

## 4. sitemap.xml (P1)

Валидный XML; только канонические https-URL со статусом 200 (без 301, 404, noindex, utm);
`lastmod` — реальная дата изменения; большой сайт — индекс sitemap.

## 5. canonical, lang, hreflang (P1–P2)

- На каждой индексируемой странице — самоссылающийся абсолютный canonical; не противоречит sitemap и 301.
- `<html lang="ru">`.
- hreflang + `x-default` — только при реальных языковых версиях.

## 6. Ответы сервера (P1)

- Несуществующий URL → **404** со своей страницей и навигацией. Soft-404 (200 на мусорный URL) — FAIL.
- Главная и ключевые страницы — 200 без лишних редиректов.
- Нет `noindex` (meta или `X-Robots-Tag`) на проде; нет mixed content; нет dev-URL в ссылках.

## 7. Контент в сыром HTML (P1 для SPA)

Яндекс и ИИ-боты почти не выполняют JS. Проверять ответ сервера (`curl`/GET без браузера):
заголовки, текст, ссылки, мета должны быть в HTML. SPA — SSR или пререндер; минимум `<noscript>` с текстом.

## 8. Производительность (P2)

- HTML до ~400 КБ, сжатие gzip/br. Horosheff: тяжёлый HTML > 2 МБ, критичный > 10 МБ.
- Картинки WebP/AVIF, до 200–300 КБ, `width`/`height`, `loading="lazy"` ниже первого экрана.
- Шрифты со своего сервера; `charset=utf-8` в заголовке ответа.
- Скрипты: нет раздутых inline-скриптов и стилей, разумное число запросов.
- Core Web Vitals локальный аудит не измеряет — смотреть в GSC/PageSpeed по запросу.

## 9. Мобильность и прочее (P2–P3)

- `<meta name="viewport" ...>`.
- favicon, apple-touch-icon, `site.webmanifest`.
- `alt` у контентных картинок, пустой — только у декоративных.

## 10. Яндекс.Метрика (P2)

Есть счётчик или нет. Номер счётчика даёт владелец сайта; код ставится в общий шаблон. Цели — по задаче владельца.

## 11. Не делать

Турбо-страницы (Яндекс свернул их в 2023, не делать); дорвеи; скрытый текст; накрутку ПФ.

## 12. Проверка перед деплоем

Падать (не деплоить), если: нет robots.txt / sitemap.xml / canonical; title или description вне
диапазонов; `h1 ≠ 1`; og:image в SVG; картинки > 500 КБ. Удобно держать эти проверки в скрипте
проекта (pre-deploy gate) и запускать его по локальной сборке (`dist/`, `public/`) или по живому
сайту только на чтение (`https://example.ru`). Туда же — GEO-проверки из `geo-ai.md` (ИИ-боты в
robots, llms.txt, JSON-LD, текст в сыром HTML, скрытые инструкции для ИИ).

## 13. Где что лежит

Каждый сайт — своя карточка проекта: прод, dev-копия, репозиторий, правила, риски. Сайт, который
существует только на проде, сначала клонировать в dev-копию и править там. Если в карточке есть
пометка о паузе (юридической, по комплаенсу) — сначала проверить её статус.
