# GEO: ИИ-ответы, боты, llms.txt, IndexNow

## 1. Политика ИИ-ботов

По умолчанию — **allow-search-block-training**: ИИ-поиск и ассистенты по запросу
пользователя могут читать и цитировать сайт; сбор для обучения моделей закрыт. Иное решение —
только владелец сайта, для конкретного сайта; записать его в карточку проекта.

| Бот | Назначение | По умолчанию |
|---|---|---|
| YandexAdditional | ИИ-ответы Яндекса (Нейро / YandexGPT) | разрешить |
| OAI-SearchBot | поиск ChatGPT | разрешить |
| ChatGPT-User | запрос пользователя ChatGPT | разрешить |
| Claude-SearchBot | поиск Claude | разрешить |
| Claude-User | запрос пользователя Claude | разрешить |
| PerplexityBot, Perplexity-User | поиск и запросы Perplexity | разрешить |
| GPTBot | обучение OpenAI | закрыть |
| ClaudeBot | обучение Anthropic | закрыть |
| CCBot | Common Crawl | закрыть |
| Google-Extended | токен: использование для обучения Gemini (не влияет на Google Поиск) | закрыть |
| Applebot-Extended | токен: обучение Apple | закрыть |
| Bytespider | ByteDance | закрыть |

Пример блока robots.txt (служебные `Disallow` повторены в именованных группах, потому что бот
с собственной группой не читает `User-agent: *`):

```
User-agent: *
Disallow: /admin
Disallow: /app/login
Clean-param: utm_source&utm_medium&utm_campaign&utm_content&utm_term&yclid&gclid&fbclid /

User-agent: YandexAdditional
User-agent: OAI-SearchBot
User-agent: ChatGPT-User
User-agent: Claude-SearchBot
User-agent: Claude-User
User-agent: PerplexityBot
User-agent: Perplexity-User
Disallow: /admin
Disallow: /app/login
Allow: /

User-agent: GPTBot
User-agent: ClaudeBot
User-agent: CCBot
User-agent: Google-Extended
User-agent: Applebot-Extended
User-agent: Bytespider
Disallow: /

Sitemap: https://<домен>/sitemap.xml
```

robots.txt — просьба, а не защита: добросовестные боты его соблюдают, остальные — нет.
Блокировка на уровне сервера (по UA/IP) — только по решению владельца сайта и с деплоем по его просьбе.

## 2. llms.txt

Опциональный файл в корне: короткое описание сайта и ссылки на ключевые страницы в Markdown.
На ранжирование не влияет. Делать, когда есть продукт или документация (SaaS, сервис, бот);
для визитки агентства — по желанию.

```
# [Название]
> [Одна-две фразы: что это и для кого]

## Основное
- [Услуги](https://<домен>/services): [что там]
- [Цены](https://<домен>/prices): [что там]
- [Контакты](https://<домен>/contacts)
```

## 3. Страницы, удобные для ИИ-ответов

- Ответ в начале: первый абзац отвечает на главный вопрос страницы без разгона.
- Заголовки-вопросы там, где люди ищут вопросом («Сколько стоит выездной форум на 100 человек»).
- Структура, которую можно цитировать кусками: короткие разделы, списки, таблицы с параметрами.
- Сущность ясна: кто компания, где, чем занимается — Organization/LocalBusiness, страницы «О нас»
  и «Контакты», `sameAs` на реальные профили.
- Автор или ответственный (Person), даты публикации и обновления.
- Ссылки на источники для цифр и утверждений.
- FAQPage / HowTo — когда содержимое реально так устроено.
- Всё в сыром HTML: ИИ-боты почти не выполняют JS.

## 4. IndexNow

Протокол мгновенного уведомления поисковиков об изменённых URL; поддерживают Яндекс и Bing
(Google — нет).
- Ключ: один на сайт, лежит открытым файлом `https://<домен>/<ключ>.txt` (это не секрет API,
  но генерировать и фиксировать его — в репозитории сайта, а не в чате).
- После деплоя — отправить список изменённых URL (GET/POST на эндпоинт IndexNow Яндекса или общий);
  включить IndexNow в Вебмастере.
- Не слать все URL при каждом деплое — только изменённые.

## 5. Как проверить GEO-готовность (аудит)

| Проверка | OK, если |
|---|---|
| Ответ в начале | первый абзац отвечает на вопрос страницы |
| Заголовки-вопросы | есть там, где уместно |
| Разметка сущности | Organization/LocalBusiness/Person валидны и совпадают с текстом |
| Свежесть | видны даты или `dateModified` в разметке |
| Структура | списки, таблицы, короткие разделы |
| Боты | политика по таблице выше, robots без противоречий |
| Сырой HTML | основной текст виден без JS |

Автоматическую часть (боты в robots.txt, llms.txt, валидность JSON-LD и сущность с `sameAs`, ≥ 100 слов
в сыром HTML, скрытые инструкции для ИИ, невидимые Unicode-символы) удобно проверять скриптом проекта
по локальной сборке или по живому сайту (`https://example.ru`, только чтение). Ответ в начале,
заголовки-вопросы и свежесть по смыслу проверяются вручную по таблице выше.
