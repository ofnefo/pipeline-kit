# ru-seo — сайты под Яндекс, Google и ИИ-ответы

Навык для русского текста и разметки сайта, которые читают другие люди и поисковики: пользователи,
Яндекс, Google, ИИ-ответы. Не нужен для ответов оператору, переписки агентов, брифов и заметок.
Порядок приоритетов: **Яндекс → Google → GEO** (ИИ-ответы). Если требования расходятся,
по умолчанию решаем в пользу Яндекса и отмечаем расхождение.

## Жёсткие правила

1. **Где лежит сайт и куда вносить правки — из карточки проекта** в вашей карте проектов
   (dev-копия, репозиторий, прод, риски). Если проект занят другим агентом — сайт не правим,
   пишем владельцу задачи.
2. **Продакшн-деплой — только с явного согласия владельца сайта для конкретного сайта.**
   По умолчанию правки идут в dev-копию или репозиторий, на прод — нет. Конфиг веб-сервера,
   редиректы, DNS и перезапуски на проде — тоже только по такому согласию.
3. **ID верификации и счётчиков вводит владелец сайта**: `yandex-verification`,
   `google-site-verification`, номер Метрики, DNS TXT. Агент оставляет место под значение и
   говорит, куда его вписать; значения не придумывает, не ищет в чужих файлах и не печатает в чат.
4. Не выдумывать данные для разметки: рейтинги, отзывы, цены, адреса, часы работы, ИНН/ОГРН —
   только реальные из брифа или с сайта.
5. Если у проекта есть общий SEO-генератор или эталонный шаблон (robots/sitemap/JSON-LD из
   конфига сайта) с другим владельцем — пользоваться им только на чтение, правки — через владельца.
6. Аудит по живому сайту — только чтение (HTTP GET страниц, robots, sitemap). Сторонние платные
   SEO-сервисы и облачные краулеры — не использовать без запроса владельца.

## Режимы

- `audit` — проверить сайт или страницу по `references/checklist.md` и `references/text-side.md`,
  выдать таблицу: пункт · статус (OK / WARN / FAIL / N/A) · где · что сделать · кто (агент / владелец).
- `fix` — подготовить правки в dev-копии сайта: robots, sitemap, мета, JSON-LD, OG, llms.txt.
  Показать дифф, проверить локально, деплой — по правилу 2.
- `text` — title, description, h1, первый абзац, FAQ под поиск для конкретных страниц
  (продающая часть текста — `ru-promo`).

## Яндекс — главное

- Один главный адрес: `https://example.ru` (или www — как решено для сайта); все зеркала (http,
  www/без www, старые домены) — **301** на главный. Директива `Host` устарела — не писать.
- robots.txt: `Sitemap:` + `Clean-param` для меток (utm_*, yclid, gclid, fbclid); не закрывать CSS,
  JS, картинки; закрыть служебное (админка, поиск, корзина, фильтры-дубли).
- Вебмастер: подтверждение прав, sitemap, главное зеркало, регион, IndexNow, проверка ответов сервера.
- Коммерческие факторы: контакты (телефон, почта, адрес/город, форма), цены или принцип расчёта,
  правовые страницы (политика обработки ПДн, cookies, оферта/договор, оплата, гарантии), реквизиты
  (юрлицо/ИП, ИНН, ОГРН) — на видимой странице, не только картинкой.
- Контент на русском, в сыром HTML (SSR/пререндер), регион и город в тексте и разметке, Метрика.

Полный чек-лист технической части — `references/checklist.md`.

## Google — что добавить сверху

Search Console (подтверждение, sitemap), canonical без конфликтов, hreflang + x-default только при
языковых версиях, валидный JSON-LD, Core Web Vitals, viewport. `Clean-param` Google игнорирует —
для него работает canonical.

## Текст и метаданные (кратко)

- `<title>` 25–70 символов (цель ~30–65), уникальный, суть страницы в начале, бренд — в конце.
- `description` 70–190 символов: что на странице + условие/выгода; без переспама.
- Ровно один `h1`, согласованный с title, но не копия; иерархия h2–h3 без пропусков.
- Первый абзац отвечает на главный вопрос страницы.
- OG: картинка JPG/PNG **1200×630**, до ~300 КБ, абсолютный URL, не SVG; `twitter:card=summary_large_image`.
- JSON-LD: Organization/LocalBusiness, WebSite, BreadcrumbList, Service, Event, FAQPage — по смыслу.

Подробно — `references/text-side.md`.

## GEO и ИИ-боты

- Политика по умолчанию — **allow-search-block-training**: поисковые и пользовательские ИИ-боты
  (YandexAdditional, OAI-SearchBot, ChatGPT-User, Claude-SearchBot, Claude-User, PerplexityBot,
  Perplexity-User) — разрешены; обучающие (GPTBot, ClaudeBot, CCBot, Google-Extended,
  Applebot-Extended) — закрыты, Bytespider — закрыт. Иное — только по решению владельца сайта.
- `llms.txt` — опционально, на ранжирование не влияет; делать для сайтов с продуктом/документацией.
- Страницы, удобные для цитирования: ответ в начале, заголовки-вопросы, списки и таблицы,
  автор/компания, даты обновления.

Подробно и пример robots — `references/geo-ai.md`.

## Порядок работы

1. Карточка проекта: где лежит сайт, куда вносить изменения, риски, кто сейчас работает с проектом.
2. Прочитать правила проекта и эталонные шаблоны, если они есть (только чтение).
3. Аудит: robots, sitemap, главная + 2–3 ключевые страницы (сырой HTML, заголовки, мета, разметка).
4. Таблица находок по приоритету: индексация → зеркала/дубли → коммерческие факторы → мета/h1 →
   разметка/OG → производительность → GEO.
5. `fix` — в dev-копии; локальная проверка (ответы 200/301/404, валидность JSON-LD, robots, sitemap).
6. Что нужно от владельца сайта: ID верификации, номер Метрики, DNS, решение по ИИ-ботам,
   явное «деплой на example.ru».
7. После правок — записать в журнал проекта, что и где изменено.

## Чего не делать

- Турбо-страницы, «SEO-тексты» с переспамом ключей, скрытый текст, доры, накрутка ПФ.
- `noindex` на весь сайт «на время», закрытие CSS/JS в robots, soft-404 (200 на несуществующие URL).
- Микроразметка с выдуманными рейтингами и отзывами.
- Деплой, перезапуск веб-сервера, правка DNS без явного согласия владельца для этого сайта.
