# ru-promo — продающие и представительские тексты

Навык для русского текста, который читают другие люди: клиенты, пользователи, зрители. Не нужен
для ответов оператору, переписки агентов, брифов и заметок.
Задача: читатель понимает, что ему предлагают, почему это ему полезно, чему можно верить
и какой следующий шаг. Работа идёт от задачи читателя, а не от списка достоинств продукта.

## Жёсткие правила

1. **Факты только из брифа.** Цены, сроки, кейсы, клиенты, отзывы, цифры, гарантии, награды,
   «более N мероприятий» — только из сообщения заказчика, приложенных материалов, профиля голоса
   (если он ведётся) или проверенной страницы проекта. Нет факта — плейсхолдер `[цена]`,
   `[кейс: клиент, задача, результат]` и вопрос в конце.
2. **Не выдумывать отзывы, рейтинги, логотипы клиентов, «нам доверяют».** Даже «для макета».
3. **«До 40%» ≠ «40%».** Доказательство сохраняет меру, базу сравнения, источник и дату.
4. **Одна страница — один главный читатель и одно главное действие.**
5. Подготовка текста не означает публикацию: выкладку на сайт и запуск рекламы делает владелец
   сайта или агент по его прямой команде для конкретного сайта или кампании.
6. Маркировка рекламы (ERID) — факт для запуска, не предмет лекций: см. `references/ads.md`.

## Шаг 0. Контекст

- Если у проекта есть редполитика или карточка голоса проекта — прочитать первой.
- Текст от первого лица (о себе, своё агентство, свой продукт) — голос по профилю голоса
  оператора, если он ведётся; иначе нейтральный регистр «страницы услуги» и вопросы о фактах.
- Где живёт сайт и куда вносить правки — карточка проекта в вашей карте проектов; в репозиторий
  сайта ничего не пишется без задачи на этот сайт.

Перед брифом — два вопроса о читателе (что он чувствует в момент чтения и как объяснить проще всего),
проверка «бриф интересный, а не полный» и проверка истории: `references/reader-first.md`.

Минимум брифа (спросить, чего нет, одним списком):
что предлагаем · кому · какую задачу читателя решаем · какое действие нужно · какие факты есть
(цена или принцип расчёта, сроки, состав, кейсы, ограничения) · где будет жить текст · регистр.

## Режимы

- `draft` — с нуля: бриф → структура → черновик → почему так → что ещё узнать.
- `audit` — по готовому тексту: диагноз → что исправить (по важности: первый экран, оффер,
  доказательства, цена/заявка, финал) → переписанный фрагмент → вопросы к фактуре.
- `ads` — варианты объявлений по углам в лимитах площадки: `references/ads.md`.

Режим не назван — пустой лист `draft`, есть текст `audit`, слово «объявление» `ads`.

## Каркас страницы (кратко)

1. **Знакомство / первый экран** — что это, для кого, какую задачу решает, почему сейчас,
   что сделать. Цена/даты/формат — рано, если без них не решить.
2. **Презентация** — продукт в ситуации читателя: сценарии, как выглядит результат, отличие
   от привычной альтернативы, честные ограничения.
3. **Детали** — состав, этапы, сроки, цена или принцип расчёта, условия, кому не подходит, FAQ.
4. **Сделка** — что входит, сколько стоит или как узнать, что будет после заявки, кнопка.

Подробно: первый экран, карточки, доказательства, FAQ, CTA, «о себе» — `references/landing.md`.
Регистры по типу продукта (массовый, B2B, технический) — `references/product-registers.md`.
Каркасы-примеры (ивент-агентство, техконференция, клубная вечеринка, SaaS, Telegram-бот) —
`references/examples-events.md`.

## Аргумент

`задача читателя → обещание → доказательство → что это значит для сделки`.
Доказательство: цифра с базой, кейс с исходной задачей, демонстрация (скрин, видео, фото
с мероприятия), условие (срок, гарантия, возврат), честное ограничение. Оценки без фактов
(«качественно», «надёжно», «индивидуальный подход») — не доказательство.

## Заголовки и CTA

- Ясность важнее остроумия: читатель за 3 секунды понимает категорию и пользу.
- Конкретика вместо превосходных степеней; слова клиента вместо слов агентства.
- CTA = глагол действия + что человек получит: «Получить смету за день», «Посмотреть демо».
  Кнопка ведёт ровно туда, что обещает. «Подробнее» — только вторичная ссылка.
- По умолчанию: «вы» со строчной, «ё», кавычки «ёлочки», заголовки без точки.
- Давать 3–5 вариантов заголовка с разными углами, если не просили один.
  Для заголовков статей и постов — 5–10 вариантов по углам и выбор через состояние читателя:
  `references/reader-first.md`.

## Формат ответа

`draft`:
```
## Бриф
Читатель / Задача читателя / Предложение / Действие / Факты / Ограничения
## Структура
## Черновик
## Почему так (3–5 пунктов)
## Что ещё нужно узнать
```
`audit`: Диагноз · Что исправить · Переписанный фрагмент · Вопросы к фактуре.
`ads`: таблица вариантов с длиной каждого поля (см. `references/ads.md`).

## Проверка перед выдачей

- Первый экран отвечает на «что, для кого, зачем, что делать».
- Каждое важное обещание чем-то подтверждено или помечено плейсхолдером.
- Нет выдуманных цифр, отзывов, клиентов; «до» не превратилось в «всегда».
- Одна аудитория, одно главное действие; цена или способ её узнать есть.
- Нет нейрошаблонов: «не просто X, а Y», тройки выгод, «раскройте потенциал», «уникальный
  подход», «команда профессионалов». Рискованные слова (лучший, самый, уникальный, бесплатно,
  без ограничений, гарантируем) — только с проверяемым основанием и условием.
- Для объявлений — длины полей посчитаны и в лимите.
- Финальная вычитка — `ru-text`.

## Связанные навыки

`ru-text` (редактура, типографика), `ru-seo` (title/description, разметка, индексация),
`ru-instructions` (справка и инструкции), `ru-voiceover` (рекламный закадр).
