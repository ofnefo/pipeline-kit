# Каркасы-примеры с плейсхолдерами

Проекты ниже вымышленные; показаны только структура и формулировки-заготовки. Всё в `[скобках]` —
факты, которые берутся из брифа или с текущего сайта проекта; ничего не дописывать «по смыслу».
Где живёт сайт и куда вносить правки — карточка проекта; в файлы сайта ничего не пишется без
отдельной задачи на этот сайт. Если у проекта есть пометка о паузе (юридической, по комплаенсу,
формы закрыты) — сначала проверить актуальный статус.

## 1. Сайт ивент-агентства (B2B + события)

Главный читатель: [роль: HR / маркетинг / ассистент руководителя] компании, которой нужно
[тип: корпоратив / выездной форум / конференция / тимбилдинг] на [масштаб] человек.
Главное действие: заявка на расчёт / звонок.

Первый экран:
```
[Тип мероприятия] для [кого] — [ключевое условие: под ключ / за N недель / в городе]
Берём на себя [площадку, программу, технику, логистику — только то, что реально делают].
[Город/регион] · от [N] участников · [цена «от», если она есть в брифе]
[Получить смету]    [Посмотреть кейсы]
```

Блоки: форматы (карточка = один формат + для какой задачи + условие) → как работаем (этапы и
сроки) → кейсы (задача клиента → что сделали → результат, фото с реальных проектов) →
что входит в смету → FAQ (перенос дат, предоплата, кто на площадке в день события, документы
для бухгалтерии) → заявка с объяснением, что будет после.

Возражения, которые обычно надо закрыть: «уложитесь ли в бюджет», «что если что-то сорвётся
в день события», «сколько нашего времени уйдёт на согласования».
Не писать без фактов: «более N мероприятий», «нам доверяют», логотипы клиентов, отзывы.

## 2. Техконференция (анонс и страница регистрации)

Главный читатель: [роль: тимлид / разработчик / CTO], который решает, тратить ли на конференцию
день и [цена билета]. Главное действие: купить билет / зарегистрироваться.

```
[Тема конференции одной строкой — о чём будет польза]
[Дата] · [город и площадка / онлайн] · [N докладов / треков — только если программа есть]
[Чем день отличается от записи на YouTube: нетворкинг, воркшопы, Q&A — что реально будет]
[Купить билет]    [Смотреть программу]
```
Регистр: технический / B2B. Доказательство — программа с именами и темами докладов, а не
«ведущие эксперты отрасли». Если программа не готова — честно «программа появится [дата]»,
и CTA «Узнать первым», а не «Купить билет». Регистрацию не призывать, пока форма закрыта.

## 3. Клубная вечеринка (анонс в соцсетях и афиша)

Главный читатель: человек, который листает ленту и выбирает, куда пойти в [день недели].
Главное действие: купить билет / отметиться «пойду».

```
[Дата, день недели] · [клуб, город]
[Лайнап или формат вечера — конкретные имена или жанр]
[Чем вечер отличается: саундсистема, гость, тема — только факты]
Вход: [цена / условия по спискам] · [возраст 18+, если нужно]
[Билеты]
```
Регистр: развлекательный — теплее и образнее, но факты (дата, место, цена, возраст) в первых строках.
Не обещать «аншлаг» и «лучшую ночь года»; срочность — только реальная («осталось [N] билетов
по ранней цене», если это правда).

## 4. SaaS для управления event-проектами

Главный читатель: [руководитель / проджект-менеджер ивент-агентства или event-отдела].

```
[Результат: все проекты, задачи и подрядчики в одном месте / меньше ручных таблиц]
[Продукт] — [категория, «полка»] для [кого], где [ключевые сценарии из брифа].
[Условие: тариф, пробный доступ, внедрение — только если есть]
[Попробовать] / [Записаться на демо]
```
Карточки = сценарии работы (вести проект, распределить задачи команде, разграничить доступ).
Возможности — только те, что есть в продукте сейчас; статус «демо» / «бета» указывать честно.
Сравнение — с Excel/чатами/общей CRM по параметрам, не оценками.

## 5. Telegram-бот для малого бизнеса

Что именно бот делает для клиента и для кого — уточнить у заказчика или взять с текущего сайта.

```
[Задача клиента, которую бот снимает]
[Бот] [делает конкретную работу] в [Telegram / где работает] — [для кого].
[Условие: как подключить, сколько стоит или пробный период — только если есть]
[Подключить] / [Посмотреть, как работает]
```
Регистр: малый бизнес / массовый — практично, без технического жаргона. Показать бота в
действии (скрин диалога, короткое видео) сильнее любого описания. Если в боте есть ИИ — назвать
конкретную помощь и что проверяет человек, без «никогда не ошибается».

## 6. «О себе» специалиста

Голос — из профиля голоса автора, если он ведётся (образцы текстов, факты, истории); факты —
только подтверждённые. Профиля нет — каркас «умею + доказательство» с плейсхолдерами
(`landing.md`, раздел 8) и список вопросов автору.
